# 🗺️ Clothes App — Roadmap v6 (Solid Base First)

> Goal: stop adding features until the foundation is **correct, consistent, and trustworthy**.
> Each phase must be *fully green* (builds, lints, runs, no known bugs) before the next begins.

---

## Guiding principles

1. **Correctness before features.** A working small app beats a broken big one.
2. **One way to do each thing.** One Firebase SDK, one navigation pattern, one styling approach.
3. **Make CLAUDE.md true.** Either the code matches the stated stack, or the doc changes to match reality.
4. **Every phase ships green.** `lint` + `typecheck` + manual smoke test pass before moving on.

---

## 🟢 PHASE 1 — Core features, done properly

Outcome: the four core loops work reliably with proper loading/empty/error states.

### 1. Auth (harden it)
- [ ] Centralize auth state in a context/provider; split navigator into **Auth stack** vs **App stack** based on `onAuthStateChanged` (remove manual `navigation.replace`).
- [ ] Add: input validation, loading spinners, inline error messages (no `alert()`), password reset, **sign-out**.
- [ ] Add a splash/loading gate while auth state resolves.

### 2. Wardrobe (the heart of the app)
- [ ] Solidify add/edit/delete with photo upload to Firebase Storage (resize/compress before upload).
- [ ] Consistent loading / empty / error states on every list.
- [ ] Category + search filtering verified end-to-end.

### 3. Outfit creation
- [ ] Settle on **one** `OutfitCreatorScreen` (manual selection MVP from `outfitcreator_2.0.md`).
- [ ] Keep the AI step as a clearly-disabled placeholder (no half-built AI).

### 4. Daily logging + analytics
- [ ] Confirm `logDailyOutfit` → wardrobe `wearCount`/`lastWorn` updates are atomic/consistent.
- [ ] `TrackUsageScreen` reads real data; verify cost-per-wear and most/least-worn math.

### Cross-cutting for Phase 1
- [ ] Centralized error handling (toast/snackbar) instead of silent `console.error`.
- [ ] Loading & empty states standardized via `EmptyState` / a shared `<Loading/>`.
- [ ] **Firestore Security Rules** committed (`firestore.rules`) so users can only read/write their own data.

**Exit criteria:** a new user can sign up → add clothes → build an outfit → log it → see stats, with no crashes and clear feedback at every step.
